# 骰子模块

## 内联协议

骰子是 Markdown 正文中的原子节点，可与普通文字混排，不存在独立投掷接口或独立请求字段。节点的 canonical 存储格式为：

```text
[[dice:v1:<UUIDv4 nodeId>:<notation>]]
```

- `nodeId` 由编辑器创建，用于把正文中的位置和服务端正式结果关联；同一帖子中不得重复。
- 表达式白名单：`NdM`、`NdM+K`、`NdM-K`；省略 `N` 时按 1 处理。
- 范围：1–100 枚、2–1000 面、修正值绝对值不超过 10000；每帖最多 20 个节点。
- 服务端解析正文并规范化表达式。围栏代码块、行内代码和反斜杠转义中的相似文本按普通文字处理；正文中的畸形骰子标记直接拒绝。
- Web 编辑器把节点显示为与正文同字号的不可编辑原子文本：未结算为 `1d20 = ?`，正式结果为 `1d20 = 14`，只用背景色区分。
- 节点可随正文移动或删除。复制生成新的 `nodeId`，剪切粘贴保留原 `nodeId`。

## 服务端结算与防篡改

- 客户端只提交含节点的 `content`，不得提交点数；正式结果由后端使用 `@dice-roller/rpg-dice-roller` 和 Node `crypto` 随机源生成。
- 已发布帖子创建时，Post 与所有 `DiceRoll` 在同一数据库事务写入。
- 未发布主题帖只把节点保存在 Post 正文中，不提前生成点数；发布事务锁定 Thread，解析所有 Post，生成全部结果后才翻转 `published=true`，失败整体回滚。
- 已发布帖编辑时按 `nodeId` 对账：移动节点复用原结果；删除节点会物理删除对应 `DiceRoll`；新增节点生成新结果。
- 同一 `nodeId` 已结算后不得修改表达式。客户端若要改变表达式，必须删除旧节点并插入带新 `nodeId` 的节点。
- BODY 发布时仍必须含骰子节点以外的可见 Markdown；普通楼层和楼中楼允许纯骰子帖子。
- 帖子软删除后结果随帖子隐藏；硬删除 Post 时由外键级联删除结果。

## 草稿与多设备同步

云草稿只保存完整 `content`。正文和其中的内联节点使用同一个 `version` 原子写入，跨设备恢复时不拆分或合并骰子字段。未发布草稿节点只显示 `?`，不会生成正式点数。

## 数据与响应

`DiceRoll` 保存 `postId`、`nodeId`、`protocolVersion`、规范化 `notation`、`quantity`、`sides`、`modifier`、`results`、`total` 与 `createdAt`。`postId + nodeId` 唯一；响应通过 `nodeId` 将结果放回正文对应位置。

开发阶段的 `20260805230000_inline_dice_nodes` 迁移会清空旧 `dice_rolls`，删除旧的独立待掷数组列，并切换为 nodeId 协议，不保留旧骰子数据。

| code | 含义 |
|------|------|
| `40003` | 骰子表达式、节点格式或节点唯一性不合法 |
| `40004` | 单帖骰子节点超过 20 个 |
