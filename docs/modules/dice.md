# 骰子模块

发布批次：`dice-v1-20260805`（后端 / Web 同批交付）。

## 协议

骰子依附于帖子，不存在可脱离帖子的独立投掷接口。客户端只提交表达式，正式结果由后端在帖子提交事务中生成。

- 表达式白名单：`NdM`、`NdM+K`、`NdM-K`；省略 `N` 时按 1 处理。
- 范围：1–100 枚、2–1000 面、修正值绝对值不超过 10000。
- 每帖最多 20 条正式结果；已发布帖编辑只能追加，已有结果不可修改或重掷。
- 后端使用 `@dice-roller/rpg-dice-roller` 解析/计算，并固定为 Node `crypto` 随机源。Web/移动端不生成正式结果。
- 结果按帖子内 `sequence` 稳定排序，响应包含规范化表达式、逐骰点数、修正值和总计。

## 发布与草稿

- 已发布主题帖：创建楼层/楼中楼、创建或编辑正文、编辑帖子时，帖子变更与 `DiceRoll` 写入处于同一数据库事务。
- 未发布主题帖：表达式存入 `Post.pendingDiceNotations`，不提前生成点数。
- 发布主题帖：锁定 Thread，先校验全部帖子待掷表达式，再生成并写入所有结果、清空待掷列表，最后更新 `published=true`。任一步失败，整个事务回滚。
- BODY 正文发布时仍必须含可见 Markdown；普通楼层和楼中楼允许纯骰子帖子。
- 编辑已发布帖子追加骰子只触发缓存失效，不作为新帖增加活动度或发送常规新帖通知。
- 帖子软删除后其骰子结果随帖子一起隐藏；关系使用级联删除处理硬删除。

## 数据与错误

`DiceRoll` 保存 `protocolVersion`、`notation`、`quantity`、`sides`、`modifier`、`results`、`total` 和 `sequence`。正式结果是审计记录，不接受客户端传入点数。

| code | 含义 |
|------|------|
| `40003` | 骰子表达式不合法或超出范围 |
| `40004` | 单帖累计骰子结果超过 20 条 |
