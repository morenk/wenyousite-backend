# @提及模块

## 规则

所有角色的单人艾特范围完全一致：

- 当前用户自己关注的人（`userFollow.followerId = 当前用户`）；
- 当前主题帖中 `ThreadMember.playerMarked = true` 的玩家身份用户；
- 排除自己、注销用户和后续的双向拉黑通知收件人。

楼主与协作者额外允许使用保留标记 `@全体玩家`。该标记只展开为当前主题帖中已标记玩家身份的用户，普通用户不能使用，也不会扩大单人艾特范围。

后端在提交正文时再次解析和校验候选范围，编辑器候选菜单只负责交互提示，不能绕过服务端权限。候选接口和正文解析都会先校验主题帖可访问性，并提前排除双向拉黑用户。单篇正文最多记录 10 个单人提及；`@全体玩家`在首次出现时保存收件人快照，后续编辑不会因为新玩家加入而追溯发送通知。

候选接口的 Swagger `data` 为 `MentionCandidatesResponseDto`；其中 `avatar` 明确为 `string | null`，`q` 明确为可选字符串，供 Web/Flutter 直接生成模型。

## 数据与同步

`PostMention.source` 区分 `DIRECT` 和 `ALL_PLAYERS`。编辑正文会同步当前提及快照：删除已移除目标；删除正文中的最后一个提及时必须清空该帖全部提及记录；通知只发送本次新增目标。通知事件键为 `mention:{postId}:{userId}`，因此队列重试和“删除后重新加回”不会重复打扰同一用户。

## 快照清空切片验收

- [x] 正文从含单人提及改为无提及时清空全部 `PostMention`
- [x] 正文从含 `@全体玩家` 改为无提及时同样清空快照
- [x] 无 `threadId` 的调用不修改提及记录
- [x] 全量测试、生产构建、提交、重启与健康检查通过

## API

| Method | Path | 用途 |
|------|------|------|
| GET | `/users/mention-candidates?threadId=&q=` | 返回“我关注的人 + 帖内标记玩家”的并集，并返回当前用户是否允许 `@全体玩家` |

候选接口仅供登录用户使用，最多返回 20 条；最终正文仍由 `MentionsService.syncMentions()` 重新解析。

## 编辑器正文协议

新版编辑器为单人提及写入稳定链接 `[@用户名](/users/{userId})`，群体提及写入 `@全体玩家`。后端同时兼容历史纯文本 `@用户名`，正文渲染器只把本站 `/users/{id}` 链接渲染为用户提及样式。
