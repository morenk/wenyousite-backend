# @提及模块

## 规则

公开主题中，所有角色的单人艾特范围完全一致：

- 当前用户自己关注的人（`userFollow.followerId = 当前用户`）；
- 当前主题帖中 `ThreadMember.playerMarked = true` 的玩家身份用户；
- 排除自己、注销用户和后续的双向拉黑通知收件人。

PRIVATE 主题在上述候选基础上再与当前 `ThreadMember` 求交集；仅被作者关注、但尚未通过邀请加入的用户不能出现在候选、写入提及快照或收到通知。最终通知投递还会再次按当前成员资格复核。

楼主与协作者额外允许使用保留标记 `@全体玩家`。服务端权限判断始终以“当前主题帖 + 当前操作用户”的复合关系为准，再检查成员角色；该标记只展开为当前主题帖中已标记玩家身份的用户，普通用户不能使用，也不会扩大单人艾特范围。

后端在提交正文时再次解析和校验候选范围，编辑器候选菜单只负责交互提示，不能绕过服务端权限。候选接口和正文解析都会先校验主题帖可访问性，并提前排除双向拉黑用户。单篇正文最多记录 10 个单人提及；`@全体玩家`在首次出现时保存收件人快照，后续编辑不会因为新玩家加入而追溯发送通知。

候选接口的 Swagger `data` 为 `MentionCandidatesResponseDto`；其中 `avatar` 明确为 `string | null`，`q` 明确为可选字符串，供 Web/Flutter 直接生成模型。

## 数据与同步

`PostMention.source` 区分 `DIRECT` 和 `ALL_PLAYERS`。编辑正文、提及快照和 `post.mentions.updated` Outbox 事件在同一事务提交：删除已移除目标；删除正文中的最后一个提及时必须清空该帖全部提及记录；通知只发送本次新增目标。通知生产者以 `mention:{postId}` 为基础键并按收件人保持唯一，因此队列重试和“删除后重新加回”不会重复打扰同一用户。

正文从含单人提及或 `@全体玩家` 改为无提及时清空全部 `PostMention`；没有 `threadId` 的调用不修改提及记录。全体玩家权限始终按 `threadId + userId` 的当前成员关系校验，只有楼主或协作者通过。

## API

| Method | Path | 用途 |
|------|------|------|
| GET | `/users/mention-candidates?threadId=&q=` | 返回“我关注的人 + 帖内标记玩家”的并集，并返回当前用户是否允许 `@全体玩家` |

候选接口仅供登录用户使用，最多返回 20 条；最终正文仍由 `MentionsService.syncMentions()` 重新解析。

## 编辑器正文协议

新版编辑器为单人提及写入稳定链接 `[@用户名](/users/{userId})`，群体提及写入 `@全体玩家`。后端同时兼容历史纯文本 `@用户名`，正文渲染器只把本站 `/users/{id}` 链接渲染为用户提及样式。

稳定链接以 URL 中的 `userId` 为身份事实，`@用户名`标签只用于显示；用户改名或标签被编辑时不改变收件人。提及解析遵循 Markdown v3 边界：允许的成对行内代码不触发通知，迁移前残留的围栏代码也做防御性忽略。历史纯文本 `@用户名`必须位于正文词边界，邮箱或普通单词内部的 `@` 不视为提及。

解析器按 `/users/{userId}` 的 ID 识别稳定链接，不依赖标签中的旧用户名；忽略任意合法长度的反引号/波浪线围栏及成对行内代码，邮箱和单词内部的 `@` 不触发历史用户名提及。
