# 字体后台简化提交与列表管理

契约版本 `5.44.0-dev.20261024.2`。HTTP 字段以[已提交 OpenAPI](../contracts/openapi.json)为准；跨端行为样例见[共享 fixtures](../contracts/admin-font-management-v1-fixtures.json)。旧上传、列表和历史字体协议保持兼容。

本次先提交契约供消费者开发：新增五个操作和携带 `submissionId` 的源上传暂时返回 `503/50301`，不写数据；其余旧入口继续工作。该提交不是已完成的运行能力，不用于部署。后续实现、迁移和隔离验证完成后才解除此限制。

## 简化提交与恢复

表单只要求文件、名称和语言（`zh/ja/en/other`，默认 `other`）。客户端内部保存提交 UUID v4、处理意图 UUID v4 和并发修订，不把它们作为表单字段。上传操作即确认允许分发、转码与分片；原字体许可仍须遵守，不伪造作者、许可或来源。

| 顺序 | 操作 | 行为 |
| --- | --- | --- |
| 1 | `POST /admin/text-fonts/submissions` | 提交 `submissionId/name/language?`；已有家族新版额外同时提供 `familyId/expectedFamilyRevision` |
| 2 | `POST /admin/text-fonts/{familyId}/sources` | 复用原二进制路径、64 MiB 上限和 `format/expectedFamilyRevision`，增加 `submissionId` 查询参数 |
| 3 | `POST /admin/text-fonts/submissions/{submissionId}/process` | 提交 `requestId`；同一启动意图重发复用，用户明确重试才生成新值 |
| 恢复 | `GET /admin/text-fonts/submissions/{submissionId}` | `job=null` 才需要上传；已有 job 直接恢复查询或处理 |

任务响应的 `submissionId` 是该 job 的准确绑定，旧手工任务为 null。详情、刷新或存在更新提交时，用 job 自身的标识恢复处理；`latestSubmissionId` 不能替代历史 job 的绑定，也不依赖浏览器会话缓存。

所有路径均以 `/api/v1` 为前缀，使用已有管理员认证与写请求保护。一次按钮点击编排创建、上传和处理，成功后先预览；发布仍是独立确认，通过旧发布端点提交精确版本及家族、目录修订。处理完成不能自动发布。

创建提交原子完成家族创建或已有家族草稿更新和不可变配置快照。新家族排到对应语言末尾；已有家族新版保持家族顺序和已保存的作者、来源、许可等补充资料，简化授权仍由本次服务器确认单独判定。自动样张随语言更新；通过旧配置入口保存过的自定义样张保留。服务端按语言生成 specimen，固定值在共享 fixtures；简化模式不接受客户端作者、许可、specimen、顺序或授权审计字段。

- `submissionId` 绑定首次规范化请求（包括首次 `expectedFamilyRevision`）和创建者。相同请求先查重再做修订检查，返回同一家族；同键不同请求或其他创建者重用返回 `409/40930`。管理员仍可恢复读取和处理既有提交。
- 源上传首次完成时原子绑定字节 SHA、长度、格式、job 和授权证据；远端暂存后仍检查家族修订。已绑定源的同字节、同格式重放返回同一 job，不因旧修订失败；换字节或格式返回 `409/40930`。网络结果未知时先 GET 恢复，已有 job 不重传。
- `requestId` 在提交内持久去重。同键重放返回当前 job；失败后重放旧键不重新执行。用户明确重试使用新键，复用已上传源和同一个 job。并发新键只允许一个活动尝试，任务状态与 Outbox 原子提交。
- 创建响应丢失时先 GET；不存在才重放同一个创建请求。上传仍在进行且查询暂未见 job 时，可以重发同一源，服务端负责并发去重。

首次绑定源时服务端记录实际上传者、确认时间、源 SHA 和规则版本 `admin-font-upload-v1`。证据持久化到 job，创建新版本时复制到版本；处理、Worker、发布均核验该路径，不能只更新家族配置。重用已有构建版本不改写原版本证据，新 job 保留本次确认。旧手工上传不带 `submissionId`，继续执行原三项权利及完整材料检查。

## 原始元数据与处理缓存

简化路径使用 `parametersVersion=2` 和独立版本的处理器；旧处理器和缓存保持可重放。构建身份包含源 SHA、处理参数版本、授权规则版本、工具链/处理器 SHA 和影响字形输出的参数（包括 specimen），不包含操作者、确认时间、提交 UUID、管理名称或排序。产物复用与不可变版本身份分别判定：同源改名要得到与提交名称一致的版本，撤回版本不能直接复用为可发布版本，不覆盖旧配置或撤回证据。

沙箱在重命名、默认轴实例化和分片前读取原字体 name 表的 `0`（copyright）、`8`（manufacturer）、`9`（designer）、`13`（license）、`14`（license URL）。严格解码，最多检查 256 条目标记录、保留 64 条；单条 UTF-8 上限 8192 字节，总文本上限 65536 字节。无法严格解码、包含 CR/LF/TAB 之外的控制字符或超限的记录整条省略并计数，不截断为貌似完整许可，不补造内容。保留合法多行版权/许可原文，JSON 正常转义，消费者按纯文本呈现。简化路径缺元数据可以处理；旧路径不因此放松材料要求。

公开 notices 只包含原字体声明、源摘要和处理修改说明，不包含账号、IP、请求标识、确认时间或授权审计对象。`fsType` 的 `0x0002/0x0100/0x0200` 限制仍拒绝，`failureCode=rights-required`，新增可选 `failureReason` 依次为 `embedding-restricted/subsetting-restricted/bitmap-only`；同时出现时按此顺序给出首项原因。损坏文件等其他失败码保持原协议。

## 管理列表

`GET /admin/text-fonts/management` 固定每页 20 条。服务端先对全量家族筛选，再计算 `total`、排序和分页，不能在当前页本地筛选。旧 `GET /admin/text-fonts?after=...&limit=...` 保持原语义。

| 参数 | 语义 |
| --- | --- |
| `q` | 名称包含匹配；NFC、去首尾空白、不区分大小写，空串不筛选，`%/_` 按文字匹配 |
| `language` | `zh/ja/en/other` |
| `status` | `draft/enabled/disabled/withdrawn` |
| `sort` | `createdAt/updatedAt/name/sortOrder`，默认 `createdAt` |
| `direction` | `asc/desc`，默认 `desc` |
| `cursor` | 不透明游标，绑定规范化筛选、排序、固定页长和 `listingRevision` |

展示名称和语言来自最后被设为当前的已发布版本（包括后来撤回的该版本），从未发布才取家族草稿；排序值来自家族。名称排序使用 NFC 后小写的确定性字节顺序。所有主排序相等时，始终按 familyId 升序决胜。家族 `createdAt/updatedAt` 用于时间排序，任务心跳或纯进度不改变家族修改时间。

状态优先级：最后当前版本已撤回为 `withdrawn`；从未发布为 `draft`；其余按家族 enabled 分为 `enabled/disabled`。`lastPublishedVersionId` 保留撤回墓碑，旧 `currentVersionId` 仍可为空；不能用最大版本号或 `publishedAt` 猜测最后当前版本。迁移优先使用现有 current 指针，其次可靠的发布审计/目录发布历史，覆盖发布 v2、回滚 v1、撤回 v1。存在历史发布却无法可靠回填时，迁移/预检必须失败并列出受影响家族 ID 供处理，不能降为 draft、猜测最大版本或恢复公众可选；不改旧 publishedAt。

列表项提供家族修订、时间、当前及最后发布版本、发布/撤回时间、最新 job 和最新提交标识。改变筛选或排序事实的写入递增 `listingRevision`；任务进度可以在每页响应时更新，并不承诺冻结任务快照。游标筛选不符或列表修订过期返回 `409/40931`，客户端保留筛选从第一页重取；格式无效返回 400。

## 原子保存顺序

Web 在本地置顶、上移和下移，然后一次 `PUT /admin/text-fonts/order`。请求包含 `expectedCatalogRevision` 与本次变更的 `groups`（最多四个不同语言）；每组提供该语言全部当前可选家族的 `items`，每项为 `familyId/expectedFamilyRevision`，数组顺序为最终展示顺序。

顺序编辑必须先加载受影响语言完整可选集合；搜索结果或当前 20 条不是完整集合。语言依据当前已发布版本，与公开目录一致。每组最多 10000 个成员；不同组或组内均不允许重复成员。

服务端在字体状态锁和同一事务内验证目录修订、所有成员修订、完整集合、语言归属及仍可选状态。遗漏、重复、跨语言、成员新增/退出或并发修改全部拒绝为 `409/40928`，不能部分保存。只更新家族排序及必要家族修订/时间，一次递增目录和列表修订、生成一次审计；顺序相同不写、不增修订、不产生审计。

新目录顺序立即生效。历史版本 ID、描述符、资源字节和正文都保持不变，不触发字体重建。其他语言组不改变。成功后客户端刷新；结果未知或冲突时重新读取完整集合，不用逐条移动请求补偿。

## 消费与验证

Web/Foundation 固定契约提交 SHA 同步 OpenAPI 和共享 fixtures。Windows Flutter 按自身门禁同步 HTTP 契约，本 VPS 不声明完成移动端门禁。共享样例覆盖超过 20 条、筛选/稳定排序/过期游标、原子多组顺序、重放和明确重试、缺元数据、显式限制、损坏文件及 64 MiB 边界。

运行实现须在独立登记的 PostgreSQL、Redis、上传目录及随机账号验证并发与失败路径，旧手工流程和历史字节需要回归。全部实现与门禁完成后再评审；本轮不合并、不部署、不重启、不做公网写入验收。


## 迁移与回退边界

迁移新增提交/请求账本、授权证据、处理参数版本、最后当前发布版本、样张来源标志和列表修订；旧版本、许可配置、发布时间、资源及正文保留。复用键从家族与产物改为独立可复用版本身份，撤回时释放该身份，支持同一字形产物的多个不可变版本。

一旦产生同一家族同产物的多个版本或 parametersVersion=2，旧二进制的去重查询和手工材料校验不能完整解释新数据，不允许直接回退旧二进制并宣称无损。兼容后端及 Worker 必须先于新 Web；切换期间按既有部署入口协调 Worker 和在途任务，不混跑不理解新参数的旧 Worker。本轮仅交付代码，不执行切换。

异常优先前滚到理解新 schema/参数版本的修复提交；临时停止简化新提交可以保留旧手工入口和只读历史，但同样必须使用兼容二进制。不得删除新版本来恢复旧唯一索引。如确需恢复备份，遵循新标签卷离线校验及显式切换门禁，单独处理备份后新增数据，不覆盖活动卷。
