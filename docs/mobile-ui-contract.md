# Flutter 移动端界面与可读性契约

状态：`required`；Flutter 客户端仓库接入后必须把本文验收矩阵纳入测试。本文只定义原生移动端的稳定界面语义，不把 PC Web 的 CSS 像素和三栏布局复制到手机。

## 1. 契约边界

移动端实现分为三层：

| 层级 | 事实源 | 是否允许平台差异 |
| --- | --- | --- |
| 机器协议 | `contracts/openapi.json`、Markdown v2 两份 fixtures、mobile-push v1 schema/fixtures | 不允许改变字段、存储格式、幂等和降级语义 |
| 界面语义 | 本文 | 可使用原生控件，但信息层级、可读性、状态和操作名称必须一致 |
| 平台布局 | Flutter 客户端 | 允许根据手机、平板、键盘和系统设置调整，不复制 PC Web 固定宽度 |

API、安全存储、重试、媒体和推送生命周期继续以 [`mobile-client-guide.md`](./mobile-client-guide.md) 为准。本文不重复字段级 schema。

## 2. 字体与文字缩放

- 正文随应用打包 Noto Sans SC，并提供真实 400、500、700 字重；不得依赖系统临时下载字体或合成粗体。
- 页面标题、主题帖标题和中文强调可使用随应用打包的 LXGW WenKai 500/700。Markdown `em` 使用文楷正体强调，不通过 `FontStyle.italic` 挤压汉字笔画。
- 数字、时间和短计数可使用 Nunito；功能理解不得依赖特殊字形。
- Flutter 字号使用逻辑像素并保留系统 `TextScaler`。禁止全局使用 `TextScaler.noScaling`、固定物理像素或把用户缩放强制限制回 1.0。
- 文字缩放到 200% 时允许页面增高、按钮换行和布局切换；不得裁掉正文、表单标签、错误信息或主要操作。

默认文字规格：

| 内容 | 字号 | 行高倍率 | 字重 |
| --- | ---: | ---: | ---: |
| 主题帖正文、楼层、独立回复 | 17 | 1.85 | 400 |
| 嵌套回复、普通私聊消息 | 16 | 1.75 | 400 |
| 页面与主题帖标题 | 24–28 | 1.35 | 700 |
| 区块标题 | 18–20 | 1.45 | 700 |
| 元数据、时间和计数 | 13–14 | 1.5 | 500 |
| 代码和表格紧凑内容 | 不低于 15 | 1.6 | 400 |

Markdown `strong` 固定使用真实 700 字重；`strong + em` 仍为 700。链接不得通过缩小字号与正文区分。删除线、引用、代码和禁用状态都必须保留足够对比度。

## 3. 阅读列与换行

- 320–599dp 手机在默认缩放下，正文左右留白通常为 16–20dp，目标每行约 18–24 个汉字。该范围是验收目标，不通过插入硬换行实现。
- 600dp 及以上设备使用居中的最大阅读列；正文上限约为 40 个全角字宽，不随平板横屏无限拉长。
- 编辑器和发布结果使用相同的正文、标题、粗体、强调、引用与代码尺度，避免编辑时可读、发布后变小。
- 中文使用正常断行；长 URL、连续英文和代码允许在自身容器换行或横向滚动，不扩大整个页面宽度。
- 表格和代码块可局部横向滚动；图片最大宽度为内容列，加载失败时保留可读替代信息。

## 4. 页面与导航

- PC Web 的 208px/72px 左侧栏不属于移动端契约，Flutter 不得在手机上压缩复制该结构。
- 手机上的创建、编辑、首聊和私聊会话是独立全屏页面，使用原生返回行为；键盘弹出后主要输入区和发送/保存操作仍可到达。
- 私聊在手机上按“会话列表 → 单个会话”导航；600dp 及以上可使用列表与会话双栏。窄屏不得把会话名称或导航标签挤成逐字竖排。
- 全局导航可以按平台采用底部栏或抽屉，但“发现、搜索、创建、通知、私聊、收藏、个人资料”必须保持可发现；当前页面和未读数不能只靠颜色表达。
- 点击通知或 FCM 推送后使用服务端 target/data 导航并重新拉取权威内容；未知目标进入对应消息中心，不猜测路由。
- 所有常用控件最小命中区域为 44×44dp；键盘、读屏标签和系统返回行为必须可用。

## 5. 正文与扩展节点

- Markdown v2 存储、规范化和可见性必须逐条通过 `contracts/markdown-v2-fixtures.json`。
- 提及、`@全体玩家`、骰子、表情和普通图片必须逐条通过 `contracts/markdown-v2-nodes-fixtures.json` 的 parse / serialize / round-trip 与复制身份规则。
- 原始 HTML 默认不渲染；独占 `<br />` 只表示顶层空段落。未知扩展节点显示安全、可复制的可读文本，不执行其中的 URL 或代码。
- 骰子节点与正文同字号；客户端只显示服务端结果，不在本地生成正式点数。
- 私聊正文是纯文本而非 Markdown，使用文本节点与明确的 HTTP(S) 链接识别；推送通知不显示私聊正文。

## 6. 状态与界面文字

- loading、error、empty、success 均有明确状态。错误说明发生了什么以及用户可以执行的下一步。
- 空状态只说明当前事实和可执行操作，不添加宣传式副标题、世界观演绎或情绪化附言。
- 同一动作在按钮、确认框和结果提示中使用同一名称，例如“发布”成功后显示“已发布”。
- 动态主题帖分类来自 `GET /thread-categories`。草稿允许 `category=null`；发布前必须选择启用 slug。未知或停用 slug 可显示历史名称/原 slug，但不能当作新的可选项。

## 7. 最低验收矩阵

Flutter 发布前至少覆盖：

| 维度 | 必测值 |
| --- | --- |
| 手机宽度 | 320、360、390dp |
| 大屏 | 600dp、横屏 |
| 文字缩放 | 100%、130%、200% |
| 字体 | 打包字体正常、字体加载失败降级 |
| 内容 | 长中文、连续英文、长 URL、粗体、强调、引用、代码、表格、图片、骰子、表情、提及 |
| 页面 | 主题帖详情、楼中楼、创建/编辑、私聊列表、私聊会话、通知目标 |
| 输入环境 | 软键盘、物理键盘、系统返回、读屏 |

验收失败条件包括：正文小于上述基线、用户缩放被关闭、文字或主要按钮被裁切、导航文字竖排、阅读列随平板无限变宽、编辑器与发布结果排版明显不一致，以及任一 Markdown/推送黄金样例无法安全降级。
